# ROADMAP — Astroverse

Статусы: `[ ]` не начато · `[~]` частично · `[x]` проверено · `[!]` заблокировано.
Обновлять только по фактической приёмке. Актуальность: 2026-11-09.

## Цель и готовность v1.0

Свободный полёт в едином пространстве от галактики до поверхности, непрерывный
масштаб, качественная графика и честные астрономические данные. Число объектов
— средство, не критерий пользовательского опыта само по себе.

- [ ] Docker на macOS/Linux поднимает приложение без ручных шагов; LAN-доступ.
- [ ] Найти → подлететь → облететь → поверхность → галактика без перезагрузки,
  дискретных переключений и необходимости читать инструкцию.
- [ ] 100k+ объектов, 60+ fps при 1080p на Apple M1 / GTX 1060, <50 draw call.
- [ ] 1 млн в каталоге; ограниченный резидентный набор без полной стартовой загрузки.
- [ ] Реальные положения на выбранную дату/Now с проверенной точностью;
  вращение/наклоны, эллиптические орбиты, эфемериды, реверс без дрейфа.
- [ ] Нет ошибок консоли/регрессий; воспроизводимость, тесты, документация.
- [ ] Публичный HTTPS, защита, логи/healthcheck, проверенное обновление/откат.

Вне v1.0: VR, моды, мультиплеер, полная процедурная вселенная, редактор планет.

## Ограничения K-1…K-9

| ID | Требование |
|---|---|
| K-1 | Points/InstancedMesh и единичные детальные меши; не меш на каждую строку |
| K-2 | Типизированные SoA; целевой core 24–40 Б/объект, не обещание размера full v2 |
| K-3 | Физические координаты отдельно от камеры/GPU; линейный масштаб сохраняет центры/расстояния |
| K-4 | Нет данных — null; synthetic явно обозначен |
| K-5 | Воспроизводимость; ID-seed допустим для процедурного оформления, не реальных орбит/положений |
| K-6 | Состояние сцены в appRef; общие GPU-ресурсы не мутировать, не вводить изменяемые глобальные синглтоны |
| K-7 | Измеримые проверки: числовые эталоны, unittest, настоящий WebGL/счётчики и визуальный просмотр |
| K-8 | Приёмка по пользовательскому сценарию, не по числу строк |
| K-9 | Все реальные тела на настоящих местах выбранной даты; frame/epoch/time/source/accuracy явны |

Контракты — [COORDINATES](docs/COORDINATES.md), источники —
[SOURCE_AUDIT](docs/SOURCE_AUDIT.md). Неизвестность не заменять ID-фазами,
нулём, снимком или прежней датой; камера/LOD/стриминг не двигают центры.

UTC [2000-01-01, 2027-06-28), 100 Horizons-векторов. Остальные реальные положения неизвестны.

5. **10.2/10.6/10.8 → 8.4**, затем **10.7/8.5**. Графическая ветка **5**

6. Продуктовая приёмка **8.7/8.8/10.9/7**, публичный выпуск **9.1–9.7**;
   защиту/health/logging 9.2–9.4 готовить заранее.

Ближайший ограниченный этап — **3.4 + расширение 3.8, приёмка 3.9**:

1. Расширить настоящий synthetic HTTP fixture до 32 секторов/2048 resident
   записей; бюджет отдельно учитывает старый и staging наборы. Проверить Now
   при заполнении бюджета, смене области/ревизии и длинных циклах вытеснения.
2. Измерить p95/max применения и LOD в браузере, ресурсы и память отдельно от
   клиента/provider. Ввести staged GPU commit только если синхронное применение
   не укладывается в выбранный бюджет; отображаемый UTC подтверждает GPU commit.
3. Закрепить политику admission/вытеснения и поведения при заполнении CPU/GPU
   бюджетов; не принимать максимум одного кадра за вместимость двух наборов Now.
4. После ближайшего этапа CPU/GPU-бюджетов — прямой потоковый импорт и
   инкрементальные обновления БД (3.7/10.0.1), до массового подключения
   источников; затем общий временной индекс/массовый streaming 3.3;
   глобальный рубеж — приёмка инфраструктуры Фазы 3 по 3.9/6.1–6.3.
   Следующий пользовательский рубеж — навигация «найти → перелететь → наблюдать»
   в физической сцене (минимум 8.1/8.2/8.3/8.6), с проверенными источниками.

Полная Фаза 4/10.5 и массовый импорт не являются предусловиями прототипа 3.3;
их координатный минимум обязателен до приёмки физического streaming.
Пять тел достаточны как реальная регрессия, расширяемость/многосекторность
проверяются явно synthetic provider. 100k карточек не доказывают 100k положений.

## Фаза 4 — Иерархические координаты `[~]`

### Проблема

Разные системы попадают в одну точку при сжатии дистанций в `equatorialXYZ`.
Нужна физическая иерархия: галактика → сектор → система → тело, сохраняющая
реальные положения и расстояния. Читаемость не оправдывает перенос объектов.

### Шаги

- [ ] 4.1 Пересмотреть `bodies/utils/coordinates.js::equatorialXYZ` — убрать сжатие, вызывающее коллизии
- [~] 4.2 Минимум сектор → система → тело реализован в physical-hierarchy/1:
  положения привязаны к моменту/ревизии, клиент вычисляет локальные разности
  через общего родителя. Production — один SSB chart пяти центров; несколько
  секторов/систем проверены synthetic-fixture. Полная иерархия каталога открыта
- [ ] 4.3 Устранить причины 53 искусственных пересечений в раскладке,
  отображаемых радиусах/LOD; не раздвигать реальные физические центры
- [~] 4.4 Минимум согласования frame/origin/unit/time и проверки смены
  origin/масштаба/сектора реализованы: 100 прежних Horizons-векторов и отдельный
  synthetic-fixture. Несовместимые frame/ревизия/момент отвергаются, неизвестность
  сохраняется. Согласование остальных астрономических источников ещё открыто

### Критерии приёмки

- [ ] Нет искусственных наложений из-за раскладки; реальные сближения и
      перекрытия в проекции сохраняются
- [ ] Иерархия галактика → сектор → система → тело работает

## Фаза 9 — Публичный деплой `[ ]`

Деплой планируется после готовности продукта; дата и масштаб первого запуска
пока не определены. До этого проектировать и проверять эксплуатационные
возможности по мере разработки, без обязательного production-развёртывания.
Целевая схема: браузер → HTTPS/reverse proxy → frontend и FastAPI; API читает
версионированную БД и обращается к ограниченному пулу вычисления позиций.
Отдельный фоновый процесс проверяет источники и готовит обновления; научные
файлы хранятся как версионированные ресурсы с проверкой хеша.

SQLite — исходный выбор. PostgreSQL рассмотреть при подтверждённой
необходимости, например по измерениям конкурентной записи или требованиям
развёртывания; миграция не считается выполненной или обязательной заранее.

### Вне фазы (честные границы)

- N-body, столкновения, приливы, тектоника — для визуального паритета не нужны.
- Гравитационное линзирование в Солнечной системе (1.75″ у лимба) — невидимо.
- Световое запаздывание и аберрация (≤ 8 мин для Солнца, ≤ 0.005°) — невидимы.
- Релятивистские эффекты, кроме чёрных дыр (Фаза 5), — пропускаем.
- Реальные текстуры экзопланет и звёзд физически невозможны.
- Точность DE440 в метрах не нужна: цель — угловая секунда, а не метр.
