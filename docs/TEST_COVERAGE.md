## Числовые и контрактные регрессии

- DE440s ↔ независимый Horizons DE441: ICRF/SSB/geometric/km/TDB, 20 дат на
  Sun 10 / Earth 399 / Moon 301 / Mercury 199 / Venus 299. Максимум **0.002420538 km**
  (Луна), Mercury **0.000002765 km**, Venus **0.000002098 km**; допуск **1 km**.
  Это регрессия на выбранных датах, не абсолютная неопределённость/ошибка
  всего интервала. accuracy=null; BSP/100 числовых эталонов сохранены.
- UTC↔TDB, timezone/leap seconds, границы интервала, unknown/null,
  неподдержанная дата/кернел, возврат даты без дрейфа. Барицентр не центр тела.
- Все 100 векторов проходят клиентские преобразования разных опор с ошибкой
  арифметики <1e-6 km на этих входах. Это roundoff, не точность эфемериды.
  Synthetic fixture проверяет разные ненулевые начала/секторы/системы,
  переназначение адресов, направления/расстояния, null, дубликаты/родителей,
  metadata/revision/time/caps. Локальные sub-ULP offsets при общем начале 1e18 km
  сохраняются, потерянная исходным double информация не восстанавливается.
- Registry: неоднозначные identity/дубликаты, center/barycenter, SHA-256,
  размеры записей/ответов, интервалы/типы, bounded pages/search, revision/ETag,
  304/409/413/422. Synthetic provider 9 объектов не требует правки сцены/решателя;
  129 в одном HTTP-секторе даёт 413, не усечение. Новых реальных тел не добавлено.
- Snapshot/index: R-tree против независимого перебора 100 запросов, октанты,
  float32/64 границы, цепь parent 1100, unknown frames/эпохи, oversized families,
  404/409/413/422/503, byte LRU, split/merge/движение семейства, independent ETag.
  Лимиты проверяются до условного 304; следующая большая карточка не блокирует
  текущую страницу. Ошибки build/commit не заменяют прежний артефакт.
- Runtime/patches: snapshot pin/atomic rename/старые транзакции,
  expected_revision, parent closure, reuse листьев, limits, startup freshness;
  legacy JSON/v1/v2 побайтово сохраняют wire/order, кириллицу/фильтры/parents.
  Python encoder↔JS reader защищён общим fixture; corrupt offsets/parents/UTF-8
  отвергаются. Проекция снимков проверена ERFA t_s2c, не положением реального тела.
- Проверяются отказы/retry/backoff источников/CLI, offline fallback, CORS,
  rate limiting, сохранение старого каталога и null. Legacy frontend:
  LOD/пикинг/dispose/детерминизм, время/follow/виды, загрузка/ошибки/виртуализация.

## Chrome DevTools MCP

Установленный MCP 1.12.0, настоящий Chrome/SwiftShader, обычный 3471 и synthetic
100000 стеки. Необработанных JS errors/неожиданных console errors нет;
SwiftShader ReadPixels warnings известны. Скриншоты основных сцен просмотрены.

| Runner / последний соответствующий этап | 3471 | 100000 |
|---|---|---|
| Physical + hierarchy | 13/13 | 13/13 |
| Legacy | 10/10 | 9/9 |
| Positions recovery (аудит) | 7/7 | 7/7 |
| Latency 200–400 ms (2026-11-08) | 20/20 непустых samples, 4 разных кадра | 20/20, 5 кадров |

Physical: точный UTC, сохранение Float64 центров, zoom/refocus/обзор,
вытеснение/возврат, sources pages/pin/304, поиск незагруженных карточек,
отсутствие полного JSON/v2. Synthetic рост 9→129→1→0 и 20 cross-sector перестановок
сохраняют renderer; после роста ёмкость 256, **1 GPU geometry / 0 textures**,
**1 draw call** непустой сцены. Рост буфера имеет стоимость; повторные циклы
её не накапливают. Реальные frame/API-цвета после synthetic восстанавливаются.

Recovery: manifest 200→sector 409→повтор всей выборки→200; второй конфликт
оставляет пустую сцену/ошибку. Pinning проверяется до 304. Неверный TDB
плоского payload отвергается; успешный frame снимает ошибку слоя отдельно
от init error. Fault injection только в изолированном Chrome; ожидаемые
HTTP 409 resource errors разрешены, uncaughtJS/GPU рост запрещены.

Latency: clock 100 ms при 250 ms и jitter двух стадий; один HTTP in-flight,
последний желаемый момент без starvation. UI явно показывает UTC кадра/лаг;
ручная дата/пауза/anchor/область отменяют старый контекст. MCP подтверждает
точную паузу/ручной скачок и те же 1 geometry/0 textures; recovery 7/7 повторён
на обычном стеке. Общие queue/timeout/backoff 3.3 ещё открыты.

Последний hierarchy 100k-прогон: legacy 44 draw call, 4083240 треугольников,
загрузка 342.6 ms, parse 158.5 ms. Snapshot-страницы через nginx:
379720 Б/12.6 ms и 279846 Б/10.1 ms. Production API RSS после physical stress:
79424 KiB — снимок процесса, не isolated benchmark. В legacy остаются крупные
перекрывающиеся synthetic-меши; функциональный smoke не принимает качество графики.

## Потоковый JSON→runtime SQLite: измерения 2026-11-06

Отдельные Linux/Docker процессы builder/API/client. Builder peak=ru_maxrss;
API RSS=/proc до/после запросов, включая Skyfield/NumPy/BSP; delivery peak=VmHWM.
Page cache ОС не включён. benchmark_streaming --million сам удаляет временные
JSON/SQLite/секции и останавливает процессы. Эти замеры предшествуют registry/
hierarchy, **не являются новым прогоном текущего payload**.

| Источник | Сборка, с | Builder peak, MiB | API до → после, MiB | Delivery peak, MiB | SQLite, Б |
|---|---:|---:|---:|---:|---:|
| seed 3471 | 0.450 | 38.38 | 54.89 → 78.45 | 27.57 | 4 038 656 |
| существующий 100k (`gen_catalog_100k.py`) | 8.922 | 43.24 | 54.88 → 78.26 | 27.54 | 94 015 488 |
| компактный synthetic 100k (`benchmark_streaming.py`) | 5.948 | 43.50 | 54.42 → 77.66 | 27.55 | 50 835 456 |
| компактный synthetic **1 млн** | **55.300** | **43.87** | **54.91 → 77.54** | **27.59** | **513 077 248** |

Новый synthetic генератор пишет JSON по строке и специально явно помечает
`source=synthetic`. Он отличается длиной карточек и строк от стандартного
100k: v2 **102000172 Б** на миллионе против **13000172 Б** стандартного 100k.
Это разные нагрузки; число строк само по себе не позволяет сравнить время
с прежним списочным writer. На **том же стандартном 100k** прежний builder
потреблял 261.09 MiB, потоковый — 43.24 MiB. Онлайн ingestion из NASA всё ещё
использует списки: измерение относится к JSON→runtime SQLite.

### Размеры и время ограниченной выдачи

Прямой localhost HTTP к отдельному API, без nginx/gzip; radius=4 ly у снимков,
page limit=512. Первое обращение и медиана следующих пяти; «первое» не
означает физически холодный filesystem cache. Одновременно работали Chrome
и другие контрольные контейнеры, поэтому это замер, а не SLA.

| Источник / запрос | Ответ, Б | Первый, мс | Медиана 5, мс |
|---|---:|---:|---:|
| seed nearby | 2895 | 1.478 | 1.643 |
| seed page512 | 23059 | 2.056 | 1.526 |
| seed search `a` | 49225 | 8.060 | 8.499 |
| стандартный 100k nearby | 2931 | 1.848 | 1.372 |
| стандартный 100k page512 | 379753 | 9.391 | 1.561 |
| стандартный 100k search `a` | 51001 | 9.118 | 9.090 |
| миллион nearby | 9583 | 1.073 | 1.092 |
| миллион page512 | 218299 | 4.617 | 1.279 |
| миллион search `a` (нет совпадений) | 2 | 300.912 | 290.176 |
| миллион positions/1, 3 центра | 2118 | 98.333 | 0.677 |

Первый `positions/1` включает checksum и ленивый импорт эфемерид; на seed
он занял 178.323 мс, последующие — 0.931 мс. Проверены 304 с пустым телом
на маршрутах, у которых есть ETag. У `/api/search` валидатора нет.
Пустой substring-поиск на миллионе остаётся линейным SQL-сканированием:
его ~290 мс — открытое ограничение, не ускоренный полнотекстовый индекс.


## Registry/hierarchy: измерения 2026-11-06

benchmark_registry: отдельный uvicorn только sources/positions и отдельный
клиент, без каталога/builder/nginx/gzip. Первый запрос включает инициализацию;
медиана следующих 5. Параллельные проверки могли влиять на время, это не SLA.

| Запрос | Ответ, Б | Первый, ms | Медиана 5, ms |
|---|---:|---:|---:|
| sources/1 пять записей | 1889 | 8.635 | 0.589 |
| sources страница 2 | 1401 | 0.746 | 0.604 |
| positions пять центров + hierarchy | 3593 | 123.136 | 0.430 |

304 пустой на всех трёх. RSS API 49696 KiB до →49932 после registry →71824 после
positions; peak клиента 29380 KiB. Предыдущий tracemalloc конструкции ещё одного
реестра из загруженных метаданных:2441 Б live/9148 Б peak; это не размер модулей,
разделяемых строк или production-каталога.

benchmark_hierarchy.mjs, Node/V8 --expose-gc поверх загруженного synthetic frame:

| Граф | Медиана decode+relative | Retained heap/граф |
|---|---:|---:|
| 5 тел, 1000 повторов | 0.006083 ms | 2570 Б, batch 500 |
| 128 секторов/512 систем/4096 тел, 50 повторов | 2.825083 ms | 708389 Б, batch 3 |

Heap delta включает batch-контейнер, не исходный frame/browser RSS/GPU bytes.
Это caps координатного компонента, не 4096 реальных эфемерид; HTTP одного
нынешнего сектора остаётся 128 центров/256 KiB.
