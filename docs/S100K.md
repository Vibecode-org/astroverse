# Synthetic S-100k

Opt-in нагрузка, не наблюдения реальных тел. Обычный `/` использует пять
проверенных DE440s центров. Запуск — [tests/README](../tests/README.md),
измерения — [s100k_report.json](s100k_report.json), история — [HISTORY](HISTORY.md).

## Данные и обычный physical-путь

Изолированный compose:5174 запускает `tests.s100k_provider`: SQLite100 секторов
по 1000 строк, без полного JSON-каталога. Реестр/API/UI явно маркируют synthetic.
Решётка 400×250: X=(column−199.5)×4000km,Z=(row−124.5)×4000km,Y=0 ICRF/SSB.
ID50001 совпадает с 50000; центры не раздвигаются. Векторы стационарны при любом
поддержанном requested UTC, evaluated_at/JD TDB соответствуют запросу, accuracy=null.

Используются те же PhysicalApp/useVerifiedFrame/PhysicalSectorManager,
PhysicalScene/Points/material/WebGLRenderer и свободная камера. Поиск выполняет
bounded SQL query, карточка/refocus — обычные UI. Стартовая камера[0,8,24]
смотрит на origin; при 1920×1080 все 100000 центров внутри frustum. Диски 5px/15px
перекрываются: submitted/in-frustum не означает 100000 различимых дисков.

## Бюджеты и атомарность

| Работа | p95/target,max ms |
|---|---:|
|Camera/LOD|1,8|
|Validation/merge/preparation slice/prelude|4,16|
|Commit (унаследованный sync apply)|16,50|
|Picking|16,50|
|Frame|p95≤16.8,p99≤33.334|
|Cold interactive|≤15000|

Frame p9516.8ms явно согласован пользователем 2026-11-12; исходный 16.667 и его
FAIL сохранены. Epsilon1e-6ms покрывает только IEEE subtraction noise.
Длинная пауза>50ms; draw calls≤1. Остальные бюджеты не ослаблялись.

Только этот профиль расширяет admission до 200000resident+staging+in-flight
строк/64MiBserialized/512MiBdecoded estimate, response≤1MiB/1000 строк.
4workers/queue≤128 сохранены. Обычные пределы 4096/128 строк не меняются.
Глобальные IDs/identities, UTC/JD/revisions проверяются до публикации.

Manager merge/flat decode отменяются между порциями. Renderer готовит XYZ/
цвета/level/слоты/AABB picking в staging по 256 строк; occupied slots — typed
bitmap, XYZ пишется напрямую в Float32. Общая квота 2ms между RAF, timeout32ms
для drain скрытой вкладки, timer fallback для browser без scheduler.
Операция/GC/preemption может превысить deadline: hard realtime не обещается.
Commit публикует целый набор синхронно; partial/ошибочный набор не виден.

LOD/picking до commit обслуживают предыдущий целый displayed frame. Rebase
компенсируется одинаковой линейной трансляцией GPU/picking/camera; staging
фиксирует опору, commit учитывает её последующее смещение. Канонические Float64
не меняются. Continuous coalescing ждёт renderer acknowledgement, сохраняя
последнее desired время; explicit context отменяет старую работу, fallback нет.

L0/L1 не скрывают loaded computed-центры;≤32L1/≤128LOD checks за RAF.
Полный обход 100k требует до 782RAF. Picking: AABB по 256 слотов, затем точная
screen-distance/depth и лексикографический ID при совпадении. Shader log-depth
сохранён. Массовый LOD/L2/поверхности в этот этап не входят.

## Память и измерения

Capacity131072:28B/slot,3670016B GPU attributes и столько же staging;
номинальный предел 7340032B. Рост освобождает старую geometry, renderer/material/
Points сохраняются. Manager decoded — модель, не RSS; GPU driver memory неизвестна.
Точность: canonical bits неизменны на паузе, CPU1e-6km, GPU absolute1e-6render/
relative1e-7, rebase≤0.05CSSpx. Допуски не являются физической uncertainty.

Чистый runner разделяет steady/picking/flight/rebase/Now/ускорение/реверс/
повторные циклы. Действия — trusted MCP/CDP input, без присваивания камеры.
Полные identity/numeric/frustum scans только вне окон; buffers≤20000samples/
metric/window. Instrumentation micro-loop оценивает нижнюю стоимость probes,
не весь overhead/GC. HTTP Resource Timing отдельно от decode CPU; async elapsed
включает yield/ожидание и не выдаётся за CPU apply. Render submission — не GPU fence.
