Сохранённые результаты завершённых прогонов; не текущий план и не утверждение
о повторном запуске тестов. Актуальная сводка — [TEST_COVERAGE](TEST_COVERAGE.md),
порядок работ — [ROADMAP](../ROADMAP.md), команды — [tests/README](../tests/README.md).
Числа разных каталогов, источников и окружений сравнивать только с их методикой.

Сквозная диагностика: в окне observer **226 fetch → 226 nginx → 224 provider**.

499 включают и отмены уже начатых ответов. Все отсутствующие в API request IDs

причину постфактум; он заменён коррелированным измерением, скрытых retry не найдено.

Production `PositionWork`: 4 admitted slots, без backlog, deadline HTTP 8 с,
503 position_busy/position_timeout, no-store/Retry-After:1. Lock polling 25 мс;
после disconnect/deadline queued work прекращается, результат проверяется перед
кэшем/выдачей. Нативный solver невозможно безопасно убить в Python thread:
слот остаётся занят до возврата. Это ограничивает накопление, не является
жёстким CPU kill. Unit и настоящий TCP/uvicorn тест с 2 слотами/150 мс прошли:
разрыв + повторные deadline вызвали только одно заблокированное вычисление;
после освобождения новый запрос успешен, отменённый результат не попал в кэш.
`position_work.py`: 56 statements / 18 branches, 100%.
Клиент учитывает Retry-After временных ошибок (bounded hint ≤2 с, минимум
configured backoff); unit проверяет 1 с, cap 2 с и неверный header. Trace UUID
имеет getRandomValues fallback для HTTP LAN origin без randomUUID.

UTC [2000-01-01, **2027-06-28**) подтверждён IERS C72/сроком leap table,
fixture utc_leap_support.json; Jan 2027 и последняя поддержанная секунда
проверены численно и через UI→HTTP→WebGL. TT−UTC сверяется с независимыми offsets
IERS; BSP, пять центров и все 100 Horizons-векторов прежние. Допуск UTC→один
binary64 JD→позиции 3 м учитывает ~40 мкс шага JD, не физическую неопределённость.
UI берёт границы из registry metadata. После границы — 422/пустая сцена;
команда Now восстанавливает текущие позиции без нового renderer.

## Дебаг physical-пути и системы, 2026-11-11
