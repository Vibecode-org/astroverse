# Реестр поддержанных источников `sources/1`

Ограниченная первая часть 10.0.1. `data/source_registry.py` содержит единственный
явный opt-in набор: Sun 10, Earth 399, Moon 301, Mercury 199, Venus 299.
Источник — прежний offline DE440s; новые тела, BSP и каталоги не подключены.
Коды, найденные при чтении BSP, не добавляются в состав автоматически.

Запись объекта связывает стабильный `id`, `target`, `identity_type`, `model_id`
и метаданные списка/маркера (`name`, `kind`, `color`). Идентичности
`body_center` / `barycenter` различаются; NAIF 0…9 нельзя пометить центрами тел.
Дубликаты ID, повторная source identity в модели, неизвестная модель,
неполные/слишком большие записи, неверные цвета, интервалы и хеши отвергаются.
Поддержаны существующие типы маркеров star/planet/moon. Нового решателя нет.

Запись модели объявляет provider/model, ревизии, solver, исходный asset и
SHA-256, ссылку источника, frame/axes/origin/unit/time scale, UTC и JD TDB
интервалы с исключённой верхней границей. `provider_revision` указывает
версию актива по его SHA-256, а не выдуманную версию организации NASA/JPL.
Единой эпохи временной эфемериды нет: `source_epoch=null` с пояснением.
Абсолютная неопределённость `accuracy=null`; числовой допуск Horizons не
подставляется вместо неё. Эта ограниченная схема не импортирует модели
с известной каталожной эпохой/ковариацией; это последующая работа.

Реестр — валидируемый неизменяемый снимок; возвращаемые метаданные копируются,
таблица targets доступна только для чтения. Состав, порядок и все метаданные
входят в SHA-256 ревизии. `ephemeris.TARGETS` сохранён как совместимое read-only
представление реестра, без самостоятельного списка. Вычислитель берёт ID,
коды центров и интервалы из реестра, сохраняя прежние Skyfield/BSP-вычисления.
Несовместимые модели нельзя вычислить в одном секторе этим provider.

## Ограниченное HTTP-чтение

```text
GET /api/sources/v1/objects?limit=128&offset=0
GET /api/sources/v1/objects?limit=2&offset=2&revision={revision}
GET /api/sources/v1/objects?q=moon&limit=128
```

Ответ: `version=sources/1`, `revision`, `objects`, связанные `models`,
`total` (всего в реестре, независимо от поиска), `next_offset` либо `null`.
`q` — case-insensitive substring ID/имени; offset относится к отфильтрованной
последовательности. Полный реестр не требуется загружать в браузер.

- limit: 1…128; offset: 0…1000000; q: до 128 символов; revision: до 64.
- Страница до 256 KiB; превышение — 413. Неверные параметры — 422.
- Несовпадение pinned revision — 409 до проверки `If-None-Match`.
- ETag зависит от содержимого страницы и общей ревизии; 304 без тела.
- Cache-Control: `public, max-age=0, must-revalidate`.
- Запись объекта до 1024 Б, модели до 8192 Б; до 128 моделей.

`positions/1` получает ревизию `positions1-{registry_sha256}-hierarchy1-ssb1` и отдельное
поле `registry_revision`. Его contract также имеет ETag, `supported_ids_total`
и ссылку `capabilities_url`; совместимый `supported_ids` ограничен первыми 128.
Полный физический сектор ограничен 128 центрами / 256 KiB, превышение — 413;
индивидуальный маршрут остаётся доступен. Это ограничение текущего
неделимого сектора, не реализация массового физического стриминга.
LRU положений остаётся 1 MiB. Неизвестное положение — null, неверная дата —
422, недоступный актив — 503, без snapshot/previous-time fallback.

`coordinates/1`, snapshot `at=422` и render-v2 не меняются. Их ревизии
независимы от эфемерид; реестр не переатрибутирует строки старого каталога.

## Frontend и ресурсы

Физический интерфейс читает первую ограниченную страницу и выполняет
серверный поиск реестра вместе с поиском каталога. Держит первую страницу
и последний результат поиска, без накопления всех страниц. Смена
`registry_revision` в положениях обновляет метаданные; временное отсутствие
frame при новой дате не запускает повторную загрузку реестра. Выбор и refocus
сохраняются; source/цвет/тип берутся из API. Отдельного списка BODIES нет.

GPU-слоты/атрибуты, рост/dispose и бюджет — [PHYSICAL_LOD](PHYSICAL_LOD.md).
CPU-центры остаются Float64, камера не меняет физические положения.

Реестр нынешних пяти тел резидентен на backend; поиск метаданных линейный,
выборка страницы выделяет только limit+1 ссылок и ограниченный результат.
Потоковый массовый импорт и дисковый реестр, обновление моделей без рестарта
и общий временной LOD ещё открыты. Production API отдаёт один сектор пяти
центров; общий клиентский менеджер нескольких секторов проверяется через
изолированный synthetic HTTP fixture, без расширения этого реестра/BSP.
Проверки/замеры: [TEST_COVERAGE.md](TEST_COVERAGE.md). Реальные векторы:
[SOURCE_AUDIT.md](SOURCE_AUDIT.md); новые тестовые provider/векторы явно synthetic.

Координатная иерархия текущего physical-пути: [HIERARCHY.md](HIERARCHY.md).

HTTP positions: четыре вычислительных слота без очереди, deadline 8 с;
503 position_busy/position_timeout с Retry-After: 1 и no-store. Disconnect
отменяет ожидание lock; результат проверяется перед кэшированием/выдачей. Нативный
solver нельзя безопасно прервать внутри вызова: его слот занят до возврата.
Расширение UTC 2027 проверено по IERS и не меняет BSP/пять центров/100 эталонов.

Ограниченный физический L0/L1, бюджеты и атомарное применение позиций:
[PHYSICAL_LOD](PHYSICAL_LOD.md). Графические размеры не измеренные радиусы.

## Каталожный SBDB adapter: 3.7-A

`data/import_sbdb.py` использует уже подключённый JPL SBDB Query API v1.0:
[официальный контракт](https://ssd-api.jpl.nasa.gov/doc/sbdb_query.html),
проверен 2026-11-10. Выбраны прежние full_name/pdes/a/per/diameter: имя,
постоянная source identity, большая полуось AU, период days, диаметр km.
Переиспользованы make_object/measurement и выделенный прежний small_body_name;
невалидное известное число отклоняется, null сохраняется. Неполное орбитальное
решение не вычисляет положение и не подключает positions-provider.

Один ограниченный запрос, count/fields/signature/завершённый JSON проверяются;
count относится ко всем совпадениям, ожидается min(count, limit) строк.
Официальный контракт предупреждает об изменениях базы между страницами:
поэтому resume/paging отсутствуют. Повтор — с начала, pin по SHA-256 входа.
Правила ID/удалений/лимиты/manifest — [SECTORS](SECTORS.md#прямой-sbdb-import-ограниченный-37-a).
Прямой импорт opt-in; штатный offline startup не зависит от JPL.
Реестр sources/1 и пять проверенных centers остаются самостоятельным opt-in.

## Целевое хранение и обновление (план, согласован 2026-11-10)

Цель охвата — все известные на дату обновления астрономические тела, а не
фиксированный список или заранее заданное число записей. По каждому источнику
и типу тел учитывать дату/ревизию, доступный и импортированный объём, фильтры,
лимиты и известные пробелы; пересечения источников разрешать через устойчивые
идентичности/aliases. TOP/страница не подтверждают полный охват. Объект можно
учесть с неизвестным положением; positions-provider требует отдельной проверки.

До массового подключения источников реестр тел и моделей должен перейти
из фиксированных списков в версионированную БД, согласованную с каталогом.
Все рабочие данные о телах и моделях должны храниться и обновляться в БД;
фиксированные JSON-файлы не служат основным каталогом, полный objects.json
для запуска не требуется. JSON ответов API, fixtures и служебных файлов допустим.
Это целевое требование; текущий JSON startup и Python opt-in реестр ещё переходные.
Стабильные ID/aliases, связи с source identity и моделями, параметры с
единицами, происхождением, точностью, временной применимостью и статусом
проверки сохраняются явно; неизвестные значения остаются null.

Этапы прямого импорта и incremental writer разделены в [ROADMAP 3.7](../ROADMAP.md).
Общая публикация, полнота/удаления/идемпотентность — [SECTORS](SECTORS.md#прямой-sbdb-import-ограниченный-37-a).
Текущий Python opt-in реестр ещё не заменён.

Фоновый процесс должен автоматически проверять источники по расписанию и
публиковать обновление после успешной валидации. Для каждого источника нужно
определить периодичность, правила полноты и проверок, права использования и
поведение при ошибке; неполный импорт не удаляет отсутствующие записи. Ошибка
сохраняет действующую ревизию и отображается в журнале и метриках. Ручной
запуск и повтор после сбоя должны быть идемпотентными. Это будущая работа.

BSP остаются отдельными версионированными ресурсами с проверкой хеша,
связанными с моделями в БД. Позиции на запрошенное время вычисляются по
моделям; хранение всех положений на все даты не предполагается. Любой
кэш результатов должен быть ограниченным и учитывать модель/ревизию,
время и систему координат. Снимки каталога не заменяют positions/1.
