# Координаты и время

## Обязательное требование продукта

Все реальные тела находятся на настоящих астрономических местах выбранной
даты; Now означает текущий момент. Положение, взаимные расстояния и точность
проверяются по независимому эталону в согласованных frame/origin/unit/time.
Детерминизм и скриншоты не заменяют астрометрию.

- Явно объявлять единицы, оси, frame/origin, исходную эпоху, момент вычисления,
  шкалу времени, источник/model/revision и известную точность. Неизвестное — null.
- Периода/радиуса недостаточно для выдумывания фазы и ориентации орбиты.
  Неизвестные положения остаются доступны как карточки, без фиктивной 3D-точки.
- Эпоха не равна времени скачивания, сборки, mtime, HTTP Date или SQLite revision;
  название источника не подтверждает ICRS/J2000. Synthetic/фон не реальные тела.
- Камера, LOD, загрузка, floating origin и линейный масштаб сохраняют физические
  центры/расстояния. Нельзя сжимать дистанции, растягивать орбиты или раздвигать
  тела ради видимости. Маркеры/подписи не являются реальными размерами.
- Возврат к одной дате даёт те же векторы независимо от истории перемотки.
  Реальные сближения/проекционные перекрытия не исправлять перемещением тел.

| Контракт | Семантика |
|---|---|
| `coordinates/1`, `/api/spatial/v1` | Каталожный снимок, не положение на дату |
| `positions/1`, `/api/positions/v1` | Геометрические центры на запрошенный момент |
| Legacy binary v2 | Render-координаты иллюстративной сцены |

Форматы нельзя переинтерпретировать. На `/` физическая сцена пяти центров;
`/?scene=legacy` использует сжатие/ID-орбиты. «Реальный масштаб» legacy не
превращает его в эфемериды. Legacy live-ephemeris (начало суток/часовой кэш)
не обеспечивает Now и не используется физическим режимом.

## Каталожные снимки `coordinates/1`

`representation=catalog_snapshot`. `equatorial`/`galactic` — способ прочтения
входных полей, не подтверждение конкретной астрономической системы отсчёта.

| Поле | Значение |
|---|---|
| unit | ly = 9 460 730 472 580 800 м (юлианский световой год) |
| Оси | x=d cos(lat) cos(lon), y=d sin(lat), z=d cos(lat) sin(lon); Y вверх, левая тройка |
| Углы | RA часы×15°, Dec градусы; Galactic l/b градусы |
| reference_system/origin/source_epoch/time_scale | null: исходные метаданные не подтверждены |
| evaluated_at/accuracy | null: эфемерида не вычисляется, оценка ошибки неизвестна |
| source | Исходная метка без переатрибуции или null; общий контракт null (смешанные источники) |
| status | unverified при полной позиции корня; unknown без неё; synthetic при source=synthetic |
| position | Несжатая проекция полей корня либо null; не подтверждённый центр |
| simulation_position | Всегда null |

Расстояние 0 сохраняется, отсутствие не превращается в 0. Полная RA/Dec
приоритетнее Galactic; меж-frame преобразования нет. gx/gy/gz, визуальные
радиусы и камера не участвуют. Потомкам/solar-телам position=null: направление
хозяина не задаёт центр планеты, членство в секторе не задаёт координаты.
Исходные поля карточки доступны для инспекции, не считаются валидированной
астрометрией.

Любой переданный `at`, включая пустой/now/J2000/ошибочный, даёт
**422 unsupported_simulation_time**. Временного диапазона нет, экстраполяции
нет. Замена снимка заново относит всё семейство к сектору; будущий запрос
на дату требует модели движения и временного индекса/консервативной траектории.

Единица — [определение IAU](https://iauarchive.eso.org/public/themes/measuring/).
Проекция проверена по [ERFA t_s2c](https://github.com/liberfa/erfa/blob/master/src/t_erfa_c.c),
с перестановкой Y/Z, допуск 1e-12 на единичном радиусе. Это проверка геометрии,
не эфемерида. Разбиение/пагинация — [SECTORS](SECTORS.md).

## Положения на дату `positions/1`

| Свойство | Значение |
|---|---|
| Состав | Sun10, Earth399, Moon301, Mercury199, Venus299; явный opt-in [реестра](SOURCES.md) |
| representation | simulation_position; геометрические центры без light-time/аберрации |
| Система/оси/начало | ICRF, native right-handed XYZ, solar-system barycenter |
| unit/time_scale | km/TDB; UTC переводится закреплённой Skyfield 1.53 |
| Источник | Offline DE440s с SHA-256, [аудит и эталоны](SOURCE_AUDIT.md) |
| source_epoch | null с пояснением: временная эфемерида без единой эпохи строки снимка |
| evaluated_at/jd_tdb | Точный UTC запроса; для JD TDB явное jd_tdb вместо evaluated_at |
| UTC | [2000-01-01T00:00:00Z, 2027-06-28T00:00:00Z), IERS C72/table expiry |
| JD TDB | [2451544.5, 2462502.5) |
| accuracy | Абсолютная неопределённость null; допуск регрессии не подставляется |
| Неизвестное тело | status=unknown, position=null, reason=no_verified_ephemeris |

Барицентры 1/2/3 не заменяют центры 199/299/399. Наличие иных кодов в BSP
не активирует тела; например Mars/Jupiter остаются unknown.

```text
GET /api/positions/v1/contract
GET /api/positions/v1/sectors/solar:verified?at=2026-11-06T12:34:56.123Z
GET /api/positions/v1/sectors/solar:verified?jd_tdb=2451545.0
GET /api/positions/v1/objects/earth?at=2026-11-06T12:34:56Z
GET /api/positions/v1/nearby?anchor=earth&dx=0&dy=0&dz=0&radius=2000000&at=2026-11-06T12:34:56Z
```

Ровно одно at/jd_tdb. UTC требует T и timezone; секунда 60 не поддержана
datetime. Неверная/неподдержанная дата 422, недоступный/изменённый BSP 503.
Без snapshot/previous-time fallback. ETag учитывает момент/содержимое/ревизию,
304 пустой. LRU 1 MiB не включает память Skyfield/NumPy/BSP; lifespan закрывает BSP.

nearby принимает конечные ICRF camera offsets km от поддержанного anchor,
координаты ±1e13 km, radius0…1e13 km. На каждом моменте вычисляются anchor и AABB
неделимого solar:verified; ответ 0/1 сектор без карточек. Общего временного
индекса звёзд нет. Сектор ограничен 128 центрами/256 KiB; превышение 413, не усечение.

Для свободной камеры nearby дополнительно принимает **все три** `ox/oy/oz`:
неподвижный ICRF/SSB origin km, каждое значение конечное в ±1e13. Тогда dx/dy/dz
отсчитываются от него; без них — от вычисленного на дату anchor. Anchor остаётся
поддержанным ID, origin не является положением тела/новой эфемеридой.
Полнота/диапазон проверяются до ETag; query.origin_km присутствует только в этом
режиме. Одна и та же свободная камера задаёт одну физическую область на разных
датах, даже когда выбранное тело уже выгружено. [Навигация](NAVIGATION.md).

## Согласованность и ошибки клиента

- nearby/sectors/objects принимают необязательный `revision` до 256 символов:
  это positions revision, не 64-символьная sources revision. Конфликт →
  **409 position_revision_changed**, no-store, до cache/If-None-Match (включая *).
  Без pin старые клиенты сохраняют ответ; валидный pin не меняет ETag/304.
- Загрузчик сверяет manifest/sector по revision, registry_revision,sectorID,
  точному UTC и JD TDB. Конфликт/409 повторяет **всю выборку один раз**;
  повторный конфликт даёт ошибку/пустую сцену. Отменённый manifest не запускает sector.
- TDB проверяется и в совместимом плоском positions/1. Неверная явно переданная
  [иерархия](HIERARCHY.md) отвергается без молчаливого fallback.
- Успешный пустой/непустой frame снимает ошибку обновления слоя. Ожидание
  frame=null её не сбрасывает; ошибка инициализации renderer сохраняется отдельно.

## Физический frontend и непрерывное время

`/` читает sources/1 и positions/1, не полный JSON/v2. Nearby и сектор относятся
к одному моменту/ревизии; пустая область вытесняет центры. Серверный поиск и
snapshot-страницы с pinning/409 используются только для справочных карточек.

CPU-векторы — JS Float64. GPU-преобразование:
`(X-originX, Z-originZ, -(Y-originY)) / 100000`. В наблюдении origin следует выбранному
центру; в свободном полёте это замороженная CPU-опора с накопленным offset.
Rebase переносит только представление, новые эфемериды не перемещают камеру.
Локальные разности — через physical-hierarchy/1. L0/L1 — графические
[маркеры](PHYSICAL_LOD.md), не измеренные размеры.
Float32 GPU имеет отдельное округление, растущее вдали от origin, не меняет
канонические векторы. Обзор/refocus/состав не пересоздают renderer;
[буферы ограниченно растут и переиспользуются](PHYSICAL_LOD.md).

Continuous хранит одну текущую выборку и последний желаемый момент. Тики
не отменяют запрос: по завершении следующий берёт последнюю дату, пропуская
промежуточные тики. Frame имеет точный evaluated_at; UI отдельно показывает
часы симуляции, UTC кадра и lag. Карточка относится к моменту кадра.
Предыдущий принятый frame виден в той же continuous-генерации с явным лагом;
это не точный Now, не интерполяция/экстраполяция и не новая точность источника.

Ручная дата/±день/Сейчас, пауза, смена anchor/области создают новый контекст:
старый кадр сразу исключается, поздние ответы игнорируются. Выход часов за
UTC-интервал или ошибочный ответ не заменяется старым успешным положением.
Now×1 синхронизируется с часами браузера. Общий менеджер сохраняет эти правила
для атомарного многосекторного набора, включая timeout/backoff и бюджеты
staging; [правила публикации](SECTORS.md). Production по-прежнему один сектор
пяти центров; общий временной индекс и dynamic LOD остаются работой 3.3/3.8.

Каталожные единицы: `au` — а.е., `period_days` — сутки; `pl_eqt` — равновесная,
а не измеренная температура поверхности. Визуальные radius/color/texture
не считаются измерениями. Различие geometric/LT/LT+S —
[JPL Horizons](https://ssd.jpl.nasa.gov/horizons/manual.html).

Изолированный [synthetic S-100k](S100K.md) задаёт стационарные искусственные
Float64 центры через positions/1 на точный requested UTC; это не наблюдения и
не snapshots. Линейная промежуточная GPU-трансляция при rebase не меняет
канонические центры и не становится источником физического положения.
