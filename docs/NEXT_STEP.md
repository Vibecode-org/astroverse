Промпт для нового сеанса:

Задача: следующий ограниченный вертикальный срез продуктовой ветки ROADMAP —
добавить один новый реально вычисляемый геометрический центр: Mars, NAIF499.
Synthetic S-100k уже имеет отдельную функциональную/динамическую приёмку;
не превращай следующий этап в повторную переработку renderer или массовый LOD.

Сначала прочитай AGENTS.md, актуальные разделы ROADMAP.md, docs/SOURCES.md,
docs/SOURCE_AUDIT.md, docs/COORDINATES.md, docs/HIERARCHY.md, docs/NAVIGATION.md,
docs/S100K.md, docs/TEST_COVERAGE.md и команды tests/README.md.
Проверь git status, сохрани чужие изменения. После анализа реализуй решение,
не останавливайся на плане. Не делай commit/push без отдельного запроса.

1. Проверь фактические SPK segments и существующий engine. Mars barycenter4
не является Mars body center499; не подменяй одно другим даже при малой разнице.
Найди и проверь первичный источник для499: координатную цепочку, native frame,
origin, time scale, диапазон, размер и условия воспроизведения. Не выбирай
kernel по одному имени/label. Используй проверяемые официальные источники.
Дополнительный ресурс должен быть checksum-pinned, с ограниченными startup/
request/memory затратами. Сохрани существующий de440s.bsp без замены.

2. Подключи модель через существующие registry/engine/positions/1/manager/UI.
Новый центр должен иметь явные identity, source/model, native frame/origin,
unit, evaluated_at/JD TDB, supported interval и accuracy. Неизвестная абсолютная
accuracy остаётся null; regression tolerance её не заменяет. Не расширяй UTC
[2000-01-01,2027-06-28) по догадке. Если новый источник покрывает меньший диапазон,
объяви это явно для модели, не ухудшая поддержку прежних пяти центров.
Без snapshot/старой даты/нулевого вектора/ID-орбиты в качестве fallback.

3. Каталог и рабочие body/model metadata должны следовать целевой DB-архитектуре;
не создавай второй viewer, отдельный список сценовых тел или новый обязательный
полный objects.json. JSON fixtures/config/API допустимы. Не расширяй этот этап
до3.7-B, всех планет, спутников Марса, L2, поверхностей или всего S-100k.

4. Сохрани все100 независимых Horizons-векторов прежних пяти центров. Добавь
отдельные численные Horizons-эталоны именно499 на заранее выбранных датах,
включая края диапазона и несколько промежуточных эпох. До оценки объяви
допуски и докажи единицы/frame/origin/time/corrections; tolerance не подгонять
под результат. Проверь невозможность случайной выдачи4 вместо499.

5. Backend/frontend tests, coverage/build; настоящий HTTP/WebGL для поиска,
карточки/refocus, смены даты/Now/реверса, free flight/rebase и выгрузки/возврата.
Проверь неподдержанную дату, отсутствующий/неверный kernel, checksum, revision,
атомарную публикацию и освобождение ресурсов. Прежние пять центров остаются
на своих численных местах. Сохрани регрессии Земли/Меркурия, log depth,
переднего picking и полюсов, обновляя только ожидаемый подтверждённый состав.
При необходимости повтори synthetic S-100k без builds/tests одновременно.
Действующий согласованный frame p95≤16.8ms; другие бюджеты не ослаблять.

6. Обнови roadmap/архитектуру/методику по фактическому результату, историю —
в docs/HISTORY.md. Сохрани машинный отчёт с источниками, hashes, диапазонами,
численными ошибками и ограничениями. Не объявляй реальный S-100k, массовый
streaming, весь registry/Фазу8 завершёнными. В конце восстанови обычный compose
без override и проверь /api/health:3471 объектов. Удаляй только свои временные
артефакты. Сообщи новый вычисляемый состав, source coverage/gaps, численную
валидацию, результаты проверок, ограничения и следующий ограниченный шаг.
