# Browser smoke (Python)

Пять независимых `unittest`-сценариев используют **sync Playwright Python** и настоящий Chrome:
`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`.
Адрес приложения фиксирован: `http://localhost:5173`.

## Запуск после завершения изменений приложения

Frontend и его API должны быть уже запущены, каталог должен содержать **3471 объект**.
Скрипт не запускает серверы, не меняет приложение и не подменяет сетевые ответы.

Из корня репозитория:

```sh
python3 -m venv /tmp/astroverse-smoke-env
/tmp/astroverse-smoke-env/bin/python -m pip install playwright
/tmp/astroverse-smoke-env/bin/python tests/browser_smoke.py
```

По умолчанию Chrome headless. Для видимого окна:

```sh
SMOKE_HEADED=1 /tmp/astroverse-smoke-env/bin/python tests/browser_smoke.py
```

Один сценарий можно выбрать аргументом, например
`BrowserSmoke.test_05_canvas_picking_returns_catalog_object`.
Окружение находится во временном каталоге: после его очистки повторите команды установки. Зависимости тестов устанавливаются отдельно от проектного npm.

Установка требует сети/PyPI; `playwright install` не нужен — используется установленный Google Chrome.

## Покрытие

1. Каталог 3471, видимый canvas, реальная сцена и продвижение render frame без `pageerror`.
2. Пауза → окрестности → галактика → Солнечная система: видимость групп, позиции камеры, продолжающийся рендер и неподвижная дата.
3. Три `+1 день` и три `-1 день`: разбор русской даты из `.scaleBadge`, движение Земли и возврат в исходную позицию; фиксация даты/позиции на паузе, движение после продолжения; `.speedChip`: ×1 → ×1.5 → ×2.25 → ×1.125.
4. Земля из `.objectRow` по точному тексту `.objectName`: панель, target в мировой позиции Земли, follow off/on, реальное перемещение камеры вместе с Землёй после продолжения, закрытие панели.
5. Фокус на Земле и закрытие панели, проекция мировой позиции на canvas, проверка frustum/видимости/отсутствия UI поверх точки, настоящий `page.mouse.click`; выбран именно каталоговый `planet`, не Three `Mesh`.

Каждый тест получает новый browser context (`ru-RU`, UTC, 1440×1000), чтобы состояние тестов не зависело от порядка. Навигация/загрузка ограничены 45 секундами, остальные ожидания — 10 секундами на операцию. `pageerror` собираются с момента до навигации и проверяются при завершении каждого теста. Консольные предупреждения не считаются `pageerror`.

## Намеренная диагностическая интроспекция

Только `page.evaluate` устанавливает `window.__astroverseSmoke` в текущей тестовой странице. Функция каждый раз начинает с DOM `#root` → ключ `__reactContainer$…` → `.stateNode.current` (актуальный HostRoot), обходит fibers и цепочки hooks и ищет `memoizedState.current.scene` (включая вложенный `current` wrapper). Имена компонентов и порядок hooks не используются; поддержаны `useRef({})` и прежний `useState({current: {}})`.

Возвращается сериализуемый JSON: view, видимость system/nearby/galaxy, camera.position, controls.target, локальная и мировая позиции Земли, followCamera/followObject, renderer.info.render.frame и текст даты. Для клика дополнительно возвращается экранная проекция; Three берётся из уже существующих объектов, без импорта/подмены библиотеки.

Это **private React internals**, намеренно используемые для диагностики, а не публичный контракт. После обновления React структура fibers может потребовать обновления тестового probe. Никаких production hooks или изменений исходников приложения нет. Probe не задаёт дату, камеру или выбор: все пользовательские изменения выполняются через UI.

После исправления приложения все пять сценариев прошли на production-сборке в установленном Chrome.
