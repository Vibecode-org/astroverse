# Astroverse

Браузерный 3D-планетарий в духе **SpaceEngine**: Солнечная система → окрестности
Солнца → Млечный Путь. Запускается одной командой в Docker, работает в обычном
браузере и доступен с других устройств в локальной сети.

> **Цель продукта:** не просто каталог объектов, а ощущение SpaceEngine —
> непрерывный масштаб от галактики до поверхности, свободный полёт и честные
> астрономические данные. Текущая версия — рабочая база на пути к этому.
> Подробный план и критерии готовности — в [ROADMAP.md](ROADMAP.md).

## Быстрый старт (Docker)

Нужны Docker Desktop / Docker Engine с Compose и браузер с WebGL 2
(Chrome, Edge, Firefox, Safari 16+). Рекомендуется 8 ГБ RAM и дискретная или
встроенная GPU не старее ~2019 года.

```bash
docker compose up --build -d
```

Открыть: **http://localhost:5173**

Остановить: `docker compose down`. Логи: `docker compose logs -f backend`
и `docker compose logs -f frontend`.

### Доступ с других устройств в локальной сети

По умолчанию порт публикуется на все интерфейсы:

```text
http://<IP-вашего-компьютера>:5173
```

IP можно узнать командой `ipconfig getifaddr en0` (macOS) или `hostname -I`
(Linux). Устройства должны быть в одной сети, а firewall — разрешать порт 5173.

Только этот компьютер:

```bash
ASTROVERSE_BIND=127.0.0.1 docker compose up -d
```

Другой порт: `ASTROVERSE_PORT=8080 docker compose up -d`. Все переменные —
в [.env.example](.env.example); скопируйте его в `.env`.

### Публичный сервер (следующий этап)

Сейчас приложение не предназначено для открытия в интернет «как есть»: нет
HTTPS и аутентификации. В бэкенде есть встроенный rate limiting для
`/api/objects` и `/api/live-ephemeris`, но перед публикацией всё равно нужен
reverse proxy (Caddy/Traefik/nginx) с TLS, домен и firewall. Backend
порт 8000 наружу не публикуется — nginx проксирует `/api` внутри Compose.
Чек-лист и требования зафиксированы в [ROADMAP.md](ROADMAP.md), Фаза 9.

## Возможности

- Солнечная система: процедурные текстуры планет и крупных спутников,
  атмосферы, кольца, пояс астероидов и пояс Койпера.
- Каталог из 3 471 объекта: планеты, карликовые планеты, луны, близкие и яркие
  звёзды, экзопланеты, туманности, скопления, чёрные дыры и галактики-соседи.
- Экзопланеты на орбитах вокруг звёзд-хозяев (Фаза 0).
- Карточки с описанием, спектральным классом, массой, температурой, периодом
  и источником.
- Окрестности Солнца: звёзды по приближённым экваториальным координатам.
- Млечный Путь: балдж, перемычка, четыре рукава, Orion Spur, пыль и положение
  Солнца.
- Поиск по имени, описанию и фактам.
- Движок времени 10 Гц: пауза, скорость ×1…×10⁶, обратное время.
- LOD deep-sky: далёкие объекты — точки, средние — инстансы, близкие —
  детальные меши; выбор работает на всех трёх уровнях.

## Каталог

`data/objects.json` — генерируемый файл, он не хранится в Git и создаётся при
старте контейнера. В `data/` лежат только исходники сборки.

- `data/catalog_seed.json` — независимый снимок: ID, оформление и справочные
  данные для офлайн-режима. Это миграция старого каталога, а не заново
  проверенная научная база; записи Messier/Caldwell требуют сверки.
- `data/catalog_config.json` — пути, URL источников, лимиты, HTTP timeout/retries
  и визуальные значения по типам.
- `data/build_catalog.py` — загрузка, нормализация, проверка и атомарная запись.
  При отказе обязательного NASA-источника прежний файл не заменяется.
- `data/catalog.py` — единый контракт `validate_catalog` / `load_catalog` /
  `write_catalog` для backend и сборщика.

Режимы `ASTROVERSE_CATALOG_MODE`:

- `offline` (по умолчанию) — сборка из снимка, без сети;
- `online` — обновление NASA/JPL перед стартом, нужен доступ к внешним сервисам;
- `existing` — только проверка готового JSON, без пересборки.

При ошибке подготовки API не запускается; причина видна в
`docker compose logs backend`. Если не удалась онлайн-сборка, `entrypoint`
автоматически повторяет её в `offline`-режиме; при ошибке офлайн-сборки API
не стартует (защита от restart-loop против NASA).

Ручная сборка (результат сохраняется на хосте):

```bash
# Онлайн: NASA Exoplanet Archive + JPL SBDB
docker compose run --rm --no-deps -e PYTHONDONTWRITEBYTECODE=1 \
  -v ./data:/app/data backend python /app/data/build_catalog.py

# Офлайн: воспроизводимая сборка из снимка
docker compose run --rm --no-deps -e PYTHONDONTWRITEBYTECODE=1 \
  -v ./data:/app/data backend python /app/data/build_catalog.py --offline
```

Неизвестные измерения остаются `null`. `ra` — часы, `dec` — градусы,
`distance_ly` — световые годы, `au` — а.е., `period_days` — сутки. NASA
`pl_eqt` — равновесная температура, не температура поверхности. `radius`,
`color`, `texture` — оформление 3D, не физические измерения.

**Важно про офлайн:** режим `offline` относится к каталогу, а не к текстурам.
Фотореалистичные текстуры планет загружаются с CDN при открытии страницы; без
интернета останутся процедурные/тёмные варианты. Это известное ограничение
(см. ROADMAP, M-2).

### Нагрузочный каталог на 100 000 объектов

`data/objects_100k.json` генерируется локально и намеренно не входит в образ
(54 МБ build context). Стек запускается через override с read-only mount:

```bash
python3 data/gen_catalog_100k.py
docker compose -f docker-compose.yml -f docker-compose.100k.yml up --build -d
```


`/api/live-ephemeris` выбирает тела по полю `jpl_command` (8 планет и Плутон).
Интерфейс пока не вызывает этот эндпоинт: сцена строится по каталогу, а живые
векторы доступны только через API. Для нового тела добавьте код в снимок и
пересоберите JSON. Малые тела не включаются автоматически, чтобы не создавать
сотни запросов к Horizons. При полном отказе NASA ответ кэшируется на 5 минут,
чтобы один недоступный апстрим не превращался в девять 10-секундных запросов
на каждый вызов.

### API каталога

- `GET /api/objects` — JSON-массив; поддерживает `?q=`, `?kind=`, `?scale=`. v1 по умолчанию.
  Любой ответ несёт `ETag`, `Cache-Control: public, max-age=0, must-revalidate`
  и `Vary: Accept`; условный запрос с `If-None-Match` получает `304` без тела
  (на 100k — ~2 мс и 0 байт вместо 2.46 МБ).
- `GET /api/objects?format=v2` — тот же набор в бинарном SoA-формате v2
  (`Content-Type: application/octet-stream`, заголовок `X-Catalog-Format: v2`).
  Явный запрос: `?format=v2` или `Accept: application/vnd.astroverse.catalog.v2`.
  nginx отдаёт его сжатым (`gzip` для `application/octet-stream`): 13 МБ
  каталога на 100k — это ~2.46 МБ по сети, при `Accept-Encoding: identity` —
  полные 13 МБ.
  См. [docs/BINARY_CATALOG.md](docs/BINARY_CATALOG.md).
- `GET /api/objects/{id}` — полная карточка одного объекта (404, если нет);
  поиск по `id` идёт через ленивый индекс каталога, а не линейным проходом.
- `GET /api/search?q=` — поиск по имени, latin-имени, описанию, фактам, мифологии
  и истории (серверный, с дебаунсом на фронтенде; клиентский фильтр — fallback).
  Индекс строится один раз на каталог: 124–129 мс → 7–10 мс на 100k.
- `GET /api/health` — статус и число объектов.

## Проверки

Backend-тесты (внутри контейнера, без установки зависимостей на хост):

```bash
docker compose build backend
docker compose run --rm --no-deps -w /app backend \
  python -m unittest discover -s tests -t . -v
```

Флаг `-w /app` обязателен: `WORKDIR` образа — `/app/backend`, тесты лежат в
`/app/tests`. Без него — `ModuleNotFoundError: data`.

Браузерные smoke-тесты (Playwright + локальный Chrome) — см.
[tests/README.md](tests/README.md). Им нужен запущенный frontend и каталог
из 3 471 объекта. Сейчас проходят 109 backend-тестов и 20 browser smoke на
каталоге 3471; ещё 4 stress-теста на 100k помечены маркером `stack100k` и
запускаются на нагрузочном стеке через `pytest tests/browser_smoke/ -m stack100k`.
Модули с маркерами `stack3471`/`stack100k` автоматически пропускаются, если
`/api/health` сообщает не то число объектов.

## Архитектура

```text
Astroverse
├── frontend  React + Three.js + Vite
│   ├── src/bodies   меши, текстуры, общие GPU-ресурсы
│   ├── src/scene    stage, buildSolarSystem, buildDeepSky, picking,
│   │                animation, viewState, lodController + LOD-слои
│   ├── src/hooks    three/время/данные
│   ├── src/components  UI (layout, controls, tabs, ui, ErrorBoundary)
│   └── src/styles   стили по зонам интерфейса (styles.css — только @import)
├── backend   FastAPI: каталог и прокси JPL Horizons
└── data      JSON-каталог, конфигурация и скрипт сборки
```

`useThree` только связывает React с `src/scene`: сцена строится один раз на пару
(каталог, режим масштаба), а переключение вида, выбор и слежение меняют
состояние на месте. Поэтому 10-герцевый движок времени не пересобирает
3 471 меш на каждом тике.

Масштабы визуализации сжаты (иначе Юпитер и галактика не умещаются в одном
кадре). Числа в карточках — справочные, по NASA / Gaia / IAU.

### Ключевые ограничения (из ROADMAP)

| # | Ограничение |
|---|---|
| K-1 | Никаких мешей на каждый объект: `Points`, `InstancedMesh` или единичные детальные меши |
| K-2 | Данные в типизированных массивах (SoA): цель 24–40 байт/объект |
| K-3 | Масштаб отображения — во фронтенде, физика — в данных |
| K-4 | Данных нет — остаётся `null`; ничего не синтезировать |
| K-5 | Никаких `Math.random()` там, где нужен детерминизм |
| K-6 | Никаких глобальных синглтонов с изменяемым состоянием |
| K-7 | Изменения проверяются измеримо: скриншот, draw call, тесты |

## Известные ограничения

- Интерфейс временный: постоянные панели видов и боковая панель. Он будет
  переработан после стабилизации LOD (Фаза 8).
- LOD включён для «Окрестностей Солнца» (звёзды, экзопланеты) и для
  галактических скоплений. Солнечная система (515 объектов), туманности,
  галактики и чёрные дыры пока рисуются отдельными мешами.
- L2-меши создаются лениво: только при входе объекта в L2 или при выборе.
  При уходе на L0/L1 меш освобождается, общие GPU-ресурсы не затрагиваются.
- Текстуры планет грузятся с CDN (M-2): без интернета фотореализм недоступен.
- Процедурные текстуры и звёздные поля детерминированы (K-5); `Math.random`
  в генерации сцены больше не используется.
- Rate limiting встроен в бэкенд, но публичного HTTPS-деплоя и аутентификации
  по-прежнему нет (Фаза 9).
- Нет CI и автоматического визуального регрессионного теста.
- `catalog_seed.json` требует научной сверки Messier/Caldwell (L-1).

формата, чтобы неверсионировать его дважды. Критерии и честные границы — в
[ROADMAP.md](ROADMAP.md).
