# Astroverse

Локальный интерактивный 3D-планетарий: Солнечная система → окрестности Солнца → Млечный Путь.

## Возможности

- Солнечная система с процедурными текстурами планет и крупных спутников, атмосферами, кольцами, поясом астероидов и поясом Койпера
- Исходный каталог из 3471 объекта (число после онлайн-обновления зависит от выборки): планеты, карликовые планеты, луны, близкие и яркие звёзды, экзопланеты, туманности, скопления, чёрные дыры и галактики-соседи
- Карточки с описанием, спектральным классом, массой, температурой, периодом и источником
- Окрестности Солнца: звёзды по приближённым экваториальным координатам
- Млечный Путь как пересечённая спираль: балдж, перемычка, четыре рукава, Orion Spur, пыль и положение Солнца
- Поиск по имени, описанию и фактам

## Запуск одной командой (Docker)

Нужен Docker Desktop / Docker Compose.

```bash
docker compose up --build
```

Открыть: http://localhost:5173 (nginx раздаёт собранный frontend и проксирует `/api` на backend).

Перед каждым запуском API контейнер автоматически пересобирает и проверяет каталог из исходного снимка (`offline`). Ручная подготовка не нужна. Frontend дожидается готовности backend.

Для загрузки свежей выборки NASA при старте:

```bash
ASTROVERSE_CATALOG_MODE=online docker compose up --build -d
```

Режимы `ASTROVERSE_CATALOG_MODE`:
- `offline` (по умолчанию) — сборка из снимка, без сети;
- `online` — обновление NASA/JPL перед стартом, требует доступности внешних сервисов;
- `existing` — только проверка готового JSON, без пересборки.

При ошибке подготовки API не запускается; причина видна в `docker compose logs backend`. Политика `restart: unless-stopped` повторит запуск контейнера. Автоматического перехода из online в offline нет.

Результат автоматической сборки хранится внутри контейнера, не меняя файлы на хосте. При пересоздании контейнера он собирается заново; для сохранения онлайн-результата на хосте используйте ручную команду с монтированием `data`, приведённую ниже.

Остановка: `Ctrl+C`, затем при необходимости `docker compose down`.

Зависимости Python и npm устанавливаются только при сборке Docker-образов. Локальные `.venv` и `node_modules` не нужны. Все команды ниже выполняются из корня проекта.

## Сборка каталога

Обычный запуск Docker выполняет сборку автоматически. Команды ниже нужны только для явного обновления/экспорта каталога или отдельной выборки.

Backend и сборщик используют единый контракт `data/catalog.py`. `data/objects.json` — генерируемый результат, он не хранится в Git и создаётся автоматически при запуске контейнера. В `data/` лежат только исходники сборки; тесты находятся в `tests/`.

- `data/catalog_seed.json` — независимый исходный снимок: сохраняет ID, оформление и справочные данные для офлайн-режима. Это миграция старого каталога, а не заново проверенная научная база. Удалены накопленные добавки старого генератора и вымышленные описания климата; оставшиеся справочные записи, особенно Messier/Caldwell, требуют отдельной сверки.
- `data/catalog_config.json` — путь снимка, URL источников, лимиты, HTTP timeout/retries и визуальные значения по типам. Пути внутри конфигурации разрешаются относительно неё.
- `data/build_catalog.py` — загрузка, нормализация, проверка и атомарная запись. При отказе обязательного NASA-источника прежний файл не заменяется.

```bash
# Онлайн: NASA Exoplanet Archive (планеты + звёзды), JPL SBDB (астероиды + кометы)
docker compose run --rm --no-deps -e PYTHONDONTWRITEBYTECODE=1 -v ./data:/app/data backend python /app/data/build_catalog.py

# Без сети: воспроизводимая сборка всех объектов из исходного снимка
docker compose run --rm --no-deps -e PYTHONDONTWRITEBYTECODE=1 -v ./data:/app/data backend python /app/data/build_catalog.py --offline

# Маленькая онлайн-выборка в отдельный существующий каталог
docker compose run --rm --no-deps -e PYTHONDONTWRITEBYTECODE=1 -v ./data:/app/data backend python /app/data/build_catalog.py --exoplanets-limit 10 --asteroids-limit 10 --comets-limit 5 --output /app/data/sample.json
```

Монтирование `./data:/app/data` сохраняет результат на хосте, а не во временном контейнере. `PYTHONDONTWRITEBYTECODE=1` предотвращает появление Python-кэшей в репозитории.

Другие типы объектов пока берутся из снимка, а не загружаются автоматически. Онлайн-выборка заменяет соответствующие категории: её размер и состав могут измениться. Совпавшие имена сохраняют ID из снимка; коллизии ID и отсутствующие родители считаются ошибкой. Пределы выборки настраиваются в config или CLI.

`--wikipedia` дополнительно обновляет описание только у объектов с явно заданным `wikipedia_title` в исходном снимке; по умолчанию таких запросов нет. Неудачное обогащение выдаёт предупреждение и сохраняет исходное описание. Мифология/история могут храниться редакционно отдельными полями, но больше не генерируются и не дописываются к описанию при каждом запуске.

Неизвестные измерения остаются `null`. `ra` хранится в часах, `dec` — в градусах, `distance_ly` — в световых годах, `au` — в а.е., `period_days` — в сутках. NASA `pl_eqt` — равновесная температура, не температура поверхности. `radius`, `color`, `texture` — оформление 3D, не физические измерения.

Backend и автоматическая сборка используют один путь: `ASTROVERSE_CATALOG_PATH` или по умолчанию `data/objects.json`; `--output` переопределяет путь только для ручной сборки. Каталог готовится до запуска API, поэтому при обычном старте отдельный перезапуск не нужен. После правок исходного снимка или конфигурации на хосте используйте `docker compose up --build -d`: эти файлы копируются в образ. Чтобы использовать вручную подготовленный `objects.json` без перезаписи при старте, запускайте с `ASTROVERSE_CATALOG_MODE=existing`.

`/api/live-ephemeris` выбирает тела по полю `jpl_command` в каталоге (в снимке настроены восемь планет и Плутон). Для подключения нового тела добавьте его код в снимок и пересоберите JSON. Малые тела не включаются автоматически, чтобы не создавать сотни синхронных запросов Horizons.

Онлайн-сборка требует доступа к `exoplanetarchive.ipac.caltech.edu` и `ssd-api.jpl.nasa.gov`, опциональное обогащение — к `ru.wikipedia.org`. API-ключи не нужны; возможны ограничения сервиса, HTTP 403/429 и таймауты. Автоматического скрытого отката на старые данные нет — для этого явно предусмотрен `--offline`.

### Проверки

Проверки выполняются внутри контейнера, без установки зависимостей на хост:

```bash
docker compose build
docker compose run --rm --no-deps -w /app backend python -m unittest discover -s tests -t . -v
```

Разовые команды (`python`, тесты, ручная сборка) entrypoint запускает без автоматической пересборки; подготовка выполняется для команды `uvicorn`.

Тесты источников работают с подменёнными HTTP-ответами, без доступа к NASA. Сквозной тест создаёт временный каталог, поднимает ограниченный по времени локальный HTTP-сервер и сравнивает весь ответ `/api/objects` с результатом сборки. Ему требуется разрешение на локальный порт.

## Архитектура

```text
Astroverse
├── frontend  React + Three.js + Vite (src/bodies — меши и текстуры,
│             src/hooks — three/время/данные, src/components — UI)
├── backend   FastAPI (отдаёт каталог, проксирует JPL Horizons)
└── data      JSON-каталог объектов + скрипт сборки
```

Масштабы визуализации сжаты (иначе Юпитер и галактика не умещаются в одном кадре). Числа в карточках — справочные, по NASA / Gaia / IAU.
